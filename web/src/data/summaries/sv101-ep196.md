## Key Facts

> **F1** CMU 31-day telemetry on 756 GPUs (A100 through B200): ≈20% execution time and ≈11% energy lost to waiting; Azure Code hits 65% idle energy, Chat workloads 52%. Lower layers (power, chips) optimize on yearly cycles with diminishing returns; upper software/orchestration (vLLM, SGLang, continuous batching, PD split) can multiply throughput several-fold. A $4M GB200 rack at 50% utilization wastes ≈$2M in power, depreciation, and opportunity cost — pushing to 90% equals a free rack.

> **F2** SGLang targets inference tax: Agent flows repeat system prompts, forcing KV recompute. RadixAttention uses a radix tree for cross-request prefix sharing; Anthropic-style optimizations reportedly cut cost 90%. Cache-aware scheduling batches similar requests like a kitchen reusing prep for three mapo tofu orders; eviction and distributed cache-aware load balancing route to GPUs that already hold KV. Continuous batching adds 2–4x throughput; PD disaggregation matches Prefill vs Decode to optimal hardware — DeepSeek and NVIDIA Dynamo place PD split at core architecture.

> **F3** RadixArk seed round includes NVIDIA, AMD, MediaTek, Databricks, plus angels like Intel CEO Lip-Bu Tan and Broadcom CEO Hock Tan; SGLang is the default Day-0 benchmark for new hardware launches. Miles training framework addresses RL post-training where generation, scoring, and weight updates fight on the same GPUs; MoE routing adds train-infer alignment complexity. Goal: demote frontier labs to shared infra — open weights from DeepSeek V4, GLM-5.2, Kimi K3 still need Day-0 engines to become tokens on NVIDIA, AMD, and emerging AI chips.

## Mental Model · *Four-Layer Infra × Soft/Hard Split × Inference-Tax Removal*

> **Components**
>
> Decompose GPU idle time across power, interconnect, system software, and orchestration; separate slow hard fixes (years, ceiling near) from high-multiple soft engineering (schedulers, kernels, cache policies). In a GPU shortage, KV reuse, continuous batching, PD split, speculative decoding, low-precision formats, and train-infer co-design turn utilization into net new capacity without new silicon purchases.
>
> **Application**
>
> Diligence AI Infra bets on measurable token-cost reduction, not narrative alone. NVDA and AMD still benefit from deploy waves, but software layers like SGLang and RadixArk capture utilization alpha and become hardware evaluation gates. Agent-heavy and RAG-heavy buyers should score prefix cache hit rates plus scheduling quality; RL post-training shops need unified Miles-class train-infer stacks. Beware CapEx without software optimization when Wall Street compares AI spend to fiber overbuild cycles.

## Key Insights

> **1.** The inference inflection is here; scarcity forces software to squeeze silicon.
>
> **Q** Why not everyone build chips?
>
> **A** Chips are costly and slow; deployed GPUs sit idle. Utilization gains equal CapEx-free capacity — Anthropic's 200+ inference engineers and Q2 profitability show software is now a frontier-lab moat.

> **2.** SGLang turns KV cache into a global reusable asset.
>
> **Q** How to cut 'inference tax'?
>
> **A** Repeated prompts/tool schemas in agents are pure waste. Radix-tree prefix sharing plus cache-aware scheduling and load balancing to GPUs with warm KV — otherwise caches don't hit; eviction retains hot system prompts and RAG docs under memory pressure.

> **3.** Inference engines are becoming AI's operating system.
>
> **Q** What is RadixArk betting?
>
> **A** Open weights ≠ deployable tokens; Day-0 multi-model, multi-chip support. Miles + SGLang closes RL post-training loops. Vision: erase frontier-lab monopoly — anyone can train and infer at the frontier.
